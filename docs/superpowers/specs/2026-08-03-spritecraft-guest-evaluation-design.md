# SpriteCraft Studio 游客模式与线上自动化评测设计

> 日期：2026-08-03
>
> 状态：核心方案已获批准，待书面复核
>
> 评测对象：https://spritecraft-studio.onrender.com

## 1. 背景与根因

线上前端使用的 Supabase 项目域名 `vgbpedxqvkybesmytzgu.supabase.co` 当前无法正常连接。注册请求稳定复现为 `Failed to fetch`，浏览器网络错误为 `ERR_CONNECTION_CLOSED`。现有 `/api/health` 仅检查 Supabase 环境变量是否存在，因此返回的 `hasSupabase: true` 不能证明认证服务真实可用。

当前产品把登录从辅助能力变成了生成前置条件：未登录时生成按钮禁用，`runGeneration()` 也会直接退出。但线上 `/api/generate` 本身没有登录校验，所以阻塞发生在前端工作流和生成后的云端保存环节。

## 2. 方案比较与决定

### 方案 A：登录可选，游客可完成核心工作流（采用）

未登录用户可以生成、预览和本地导出；登录仅用于跨设备云端保存。Supabase 故障不会阻断核心价值链。该方案改动最小，符合产品最初“登录为辅助能力”的定位，也能最快恢复线上评测。

### 方案 B：先恢复或更换 Supabase 项目

更新有效的 Supabase URL、匿名密钥和服务端密钥后重新部署，可恢复完整云端素材库测试。但它依赖 Supabase 控制台权限、项目状态和邮件配置，完成时间不确定，不适合作为启动生成基线的前置条件。

### 方案 C：仅绕过界面直调生成 API

可立即完成部分生成质量基线，但无法真实验证未登录用户的生成、预览、导出和错误恢复体验，也会掩盖登录阻断问题。仅作为评测执行器的底层通道，不作为产品修复方案。

决定采用方案 A，并把方案 B 作为独立后续修复。用户已授权按方案 A 修改和部署。

## 3. 产品行为设计

### 3.1 游客工作流

1. 游客设置素材类型、Prompt、风格、尺寸、帧数、调色板、seed 和透明背景。
2. 点击生成后，前端调用现有 `/api/generate`。
3. 生成成功后，素材进入当前浏览器页面内存，可预览、收藏和导出。
4. 游客刷新或关闭页面后不承诺恢复素材；界面需明确提示“当前会话可用，登录后可云端保存”。

### 3.2 登录用户工作流

1. 存在有效 Supabase 会话时，生成完成后继续调用 `/api/library` 保存素材。
2. 云端保存成功时使用服务端返回的带签名 URL 素材。
3. 云端保存失败时保留已经生成的本地素材，任务显示“生成成功、云端保存失败”，不能把生成任务整体伪装成失败或丢失结果。

### 3.3 登录组件

登录和注册入口继续保留，但文案从“登录后才能生成”调整为“登录用于云端保存”。认证失败显示真实错误，不影响游客继续使用生成、预览和本地导出。

## 4. 数据流与组件边界

- `ControlsPanel`：生成按钮只由生成中状态控制，不再依赖登录状态。
- `App.runGeneration()`：始终先执行生成；只有存在有效 `accessToken` 时才进入云端保存分支。
- `apiGeneration`：保持现有生成 API 调用，不加入伪素材或认证耦合。
- `cloudLibrary`：保持为可选持久化适配层；失败不得清空本地结果。
- `InspectorPanel` 与导出器：继续消费当前内存中的 `GameAsset`，无需登录。
- 服务端 `/api/generate`：本轮不改变公开访问口径；访问控制与成本防滥用另列风险，不混入本次快速恢复。

## 5. 错误处理

- Seedream 失败：任务标记失败，显示服务端真实错误，保留请求时间和失败类型。
- Supabase 不可达：登录/注册显示认证错误，但生成按钮保持可用。
- 云端保存失败：保留生成结果并显示降级提示。
- 导出失败：保留现有非空校验和明确错误，不生成空文件。
- 游客刷新：不承诺恢复，并通过文案避免把内存态误解为云端保存。

## 6. 评测方案口径调整

本调整发生在正式基线运行前，需要作为 v0.1 的执行前产品决策留痕，不能覆盖原始文档：

- `FUN-001` 的新预期为“未登录可生成、预览和本地导出；界面明确提示未云端保存”。
- `FUN-002` 与 `FUN-011` 仍按原口径检查。Supabase 未恢复时必须记录为失败或外部依赖阻断，不得记为通过。
- A 层 48 组生成基线可使用同一线上 `/api/generate` 自动执行，并保留首次结果和所有失败。
- B 层使用浏览器自动化验证游客主流程、参数联动、帧数、透明通道和导出结构；认证与云端恢复单独报告。
- C 层只能自动生成记录模板和统计结果，5 名受试者的真实任务数据不得由脚本或模型伪造。

## 7. 验证与验收标准

### 自动化回归

- 无 Supabase 会话时，生成按钮可用。
- 游客生成成功后，素材进入页面并可选择四类导出。
- 游客生成不会调用 `/api/library`。
- 有会话时仍尝试保存云端；保存失败时生成素材不丢失。
- Seedream 失败时不出现本地样例或假成功状态。

### 工程验证

- 新增最小化的 Vitest/React Testing Library 回归测试，覆盖游客生成与云端保存降级分支。
- `npm run typecheck`、`npm run lint`、`npm run build` 全部通过。
- 部署后用 Playwright 对线上地址执行游客 Smoke Test，并检查浏览器控制台、下载文件和 `/api/health`。

### 上线验收

- 未登录用户可从参数设置完成一次真实生成、预览和 PNG/JSON/ZIP 导出。
- 认证服务不可达不会阻断游客主流程。
- 线上失败信息真实可见，且不会用本地样例替代模型输出。
- 正式 48 组基线在 6 类各 1 例 Smoke Test 通过并确认预算后开始。

## 8. 实施隔离与部署

当前工作目录位于旧的 `pr/3-mock-workflow` 分支，并含大量与 GitHub `main` 对应但未提交的文件。实施必须从远端 `main` 创建隔离工作区和功能分支，只带入本设计、游客模式修复、测试与评测文件；不得提交当前目录中的无关改动。

部署前先完成本地测试和线上变更清单复核。Render 对 `main` 开启自动部署，因此只有经确认的功能提交进入 `main` 后才触发正式部署。

## 9. 非目标与已知风险

- 本轮不创建或迁移 Supabase 项目。
- 本轮不把游客素材持久化到浏览器存储。
- 本轮不实现 API 配额、验证码或防滥用；公开生成 API 的成本风险需在基线结束后单独处理。
- 本轮不把自动模型评分冒充两名独立人工评分者。
- Supabase 未恢复前，不能宣称注册、登录和跨会话云端恢复已通过评测。
